Initialize the current CMDB repository without touching business code. First perform preflight. Create local directories if absent under the repository's `plan/` directory: `plan/00_Dashboard/`, `plan/01_Requirements/`, `plan/02_Bugs/`, plus `.cmdb-dev/` at the repository root. Never create projection directories at the repository root; `plan/` may already contain human-maintained planning documents — do not modify them. Create read-only-intent Obsidian dashboard pages under `plan/00_Dashboard/` from the plugin templates: `首页.md` (entry page linking the other views), `研发控制台.md` (Waiting Approval/Active/Blocked/Open Bugs/Done plus GitHub metadata), `研发看板.md` (dataviewjs status columns), `需求列表.md` (full work item table); all views are Dataview queries over `plan/01_Requirements` and `plan/02_Bugs` with no hand-written state. Create `.cmdb-dev/state.json`. Prefer excluding these local projections in `.git/info/exclude` (exclude `plan/` and `.cmdb-dev/`), not shared `.gitignore`. Check `.github/workflows/build-image.yml`; if absent and a usable Dockerfile exists, create a `CMDB Build Image` workflow that runs on default branch push and v* tags, uses GHCR, permissions contents:read/packages:write, Buildx/login/metadata/build-push, and emits digest evidence. Reuse an equivalent existing workflow instead of duplicating. If no Dockerfile exists, do not invent it; report blocker. Do not create a development Issue. Return files changed, GitHub connectivity, workflow status, blockers, next command. Notes: $ARGUMENTS
