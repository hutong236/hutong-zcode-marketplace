The user explicitly approves: $ARGUMENTS. Act as Primary Agent Orchestrator and use `cmdb-control` MCP tools for every state/authority action. Call `cmdb_status` with GitHub refresh when resuming across sessions or when local state is stale or suspect; if this session just created/synced the Work Item, the revision-guarded local state is enough. Then `cmdb_transition(approve_requirement, actor=human:<identity>)` to record Gate A. Resolve and fetch the current default branch, then call `cmdb_worktree_create` with explicit base `origin/<default-branch>`; pin Planner completion, Coder, Tester, and Reviewer to the returned path. Record every milestone with `cmdb_transition`; never hand-edit state. After the Coder completes, dispatch Tester and Reviewer in the same round — Reviewer is read-only, so parallel dispatch does not violate the single-writer rule; proceed only when both results are in (Tester passed + Reviewer approved), and on any failure return to Coder and re-dispatch both. Stop when the three-round rework budget blocks. After reviewer approval commit only related files, call `cmdb_authorize(git-push)` and use the returned token for exactly one push from the recorded worktree cwd. Create a PR with `Refs #issue`, record `pr_created`, then call `cmdb_verify_pr_checks`; never submit `checks_passed` through the generic transition tool. While the check run is still in progress, never block or poll in the foreground: start one background `gh run watch <run-id> --exit-status --interval 30` Bash task, tell the user the checks are running, and end the turn; the completion notification — or a later resume finding the item `pr_checking`, which runs one `gh run list` query and re-arms the watch while the run is still going — continues with verification and the merge gate. Public repositories require GitHub-enforced checks. Private repositories without paid branch protection use the exact-SHA control-plane guard. High risk stops at waiting_human_merge for `/cmdb_merge_approve`; low/medium risk under either guard mode proceeds with one merge. Every merge command must include `--match-head-commit <persisted-pr-head-sha>` and needs no token — the guard state-verifies merges from the `merging` state. Verify merged SHA, record pr_merged, then split by the persisted delivery policy: when delivery_required is false and skip_allowed is true, immediately record `policy_skip` (actor orchestrator, evidence citing the Gate A approval: Issue number, approving human actor, delivery_reason), close the exact Issue once (state-verified, no token), record issue_closed, housekeep the merged worktree — plain `git worktree remove <worktree_path>` (never `--force`) then `git branch -d <branch>` from the managed repository — and report Done — no human stop; otherwise STOP at waiting_tag_confirm for tag confirmation. Do not invoke the legacy state CLI or bypass MCP.
