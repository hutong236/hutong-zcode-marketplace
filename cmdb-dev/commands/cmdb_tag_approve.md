The user explicitly confirms Gate C for $ARGUMENTS. Call `cmdb_status` with GitHub refresh when resuming across sessions or when local state is stale or suspect (a merge transition performed in this session is revision-guarded and fresh); require waiting_tag_confirm and merged SHA. When the item still sits at `waiting_human_merge` because the user issued this confirmation early, treat that one explicit human confirmation as covering Gate B plus Gate C — provided `cmdb_verify_pr_checks` has passed: record `approve_merge`, perform exactly one authorized merge with `--match-head-commit <persisted-pr-head-sha>`, record `pr_merged`, then continue the tag path in the same turn; never merge on unverified, missing, or failed checks. For tag delivery call `cmdb_transition(approve_tag, actor=human:<identity>, patch.image_tag=<confirmed strict SemVer>)`; for skip call approve_skip — the manual override for an item already parked at waiting_tag_confirm (the normal skip-allowed path closed itself via policy_skip right after merge). Skip is valid only under persisted delivery policy; call `cmdb_authorize(issue-close)`, close the exact Issue once, then record issue_closed. Tag path requires collision and default-branch ancestry checks. Call `cmdb_authorize(git-tag)` for one annotated-tag command naming both the confirmed tag and exact merged SHA, then a fresh `cmdb_authorize(git-push)` to push only that tag. Run protected commands with the Bash tool cwd set directly to the managed repository; do not use `cd` or `git -C`. After the tag push, do not block on the image build: start one background `gh run watch <run-id> --exit-status --interval 30` Bash task, tell the user the build is running, and end the turn. Only when the run has concluded — via the background-task notification, or a later resume that finds the item `building` and one `gh run list` shows it finished — dispatch Build Checker; independently collect Actions artifact, Release metadata, GHCR digest, SBOM and provenance. Pass the two metadata objects and registry evidence to `cmdb_verify_delivery`; only that tool may record image_verified. Then authorize/close the exact Issue once and record issue_closed. Any build/evidence failure records block and leaves the Issue open. Never batch protected actions or invoke the legacy state CLI.
