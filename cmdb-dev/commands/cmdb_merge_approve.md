The user explicitly authorizes merge for $ARGUMENTS. This command covers high-risk work and every private-repository control-plane merge. Call `cmdb_status` with GitHub refresh when resuming across sessions or when local state is stale or suspect (a `cmdb_verify_pr_checks` performed in this session is revision-guarded and fresh), and verify waiting_human_merge, passed Tester/Reviewer/workflow checks, persisted `pr_head_sha`, a verified merge guard, and no blocker. Call `cmdb_transition(approve_merge, actor=human:<identity>)` to persist Gate B; approval never bypasses checks. Call `cmdb_authorize(pr-merge)` and use its token for exactly one repository-compatible merge command that includes `--match-head-commit <persisted-pr-head-sha>`. Verify merged SHA, call `cmdb_transition(pr_merged)` with that SHA, then split by the persisted delivery policy: when delivery_required is false and skip_allowed is true, record `policy_skip` citing the Gate A approval, authorize one Issue close, record issue_closed, housekeep the merged worktree — plain `git worktree remove <worktree_path>` (never `--force`) then `git branch -d <branch>` from the managed repository — and report Done; otherwise STOP at waiting_tag_confirm. Never invoke the legacy state CLI.
