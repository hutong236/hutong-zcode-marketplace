Act as Primary Agent Orchestrator for a lightweight batched release: $ARGUMENTS. Zero Work Items throughout — never call `hulane_open_work_item`, `hulane_verify_delivery`, or any state-writing tool, and do not open or close any Issue. If no strict SemVer version (vX.Y.Z) was supplied, STOP and ask the user for the version; never guess or bump one yourself. With a version, first show the batch before anything else: report the merges since the latest `v*` tag (`git log --oneline <last-tag>..origin/main` plus `gh pr list --state merged`) and echo the target version together with the current origin/main HEAD SHA from `git ls-remote origin refs/heads/main`. Then call `hulane_authorize_release(version, sha=<origin/main HEAD>, actor=orchestrator, evidence quoting the user's release request and the date)`; it hardens against the remote (SHA must equal origin/main HEAD, tag must not exist there) and returns two single-use tokens pinned to exactly that version+SHA. Execute exactly two independent Bash calls, each with the working directory set directly on the tool to the managed repository (never via `cd`, `git -C`, or a subshell) and exactly one operation, in this order: first `HULANE_RELEASE_TAG_TOKEN=<tag_token> git tag -a <vX.Y.Z> -m "Release <vX.Y.Z>" <sha>` creates the annotated tag on the pinned main HEAD; then read the tag OBJECT SHA with plain `git rev-parse <vX.Y.Z>` (never append `^{}` — that dereferences to the commit SHA) and push exactly that object with `HULANE_RELEASE_PUSH_TOKEN=<push_token> git push origin <tag对象SHA>:refs/tags/<vX.Y.Z>`. The push ships the annotated tag object itself (Gate A ruling #2 keeps annotated tags): a bare `<vX.Y.Z>` refspec is rejected by the guard, and token consumption verifies the refspec object is an annotated tag, is the local pinned version's tag object, and dereferences to the pinned commit SHA. Never combine the two calls into one, chain a repair, or reuse a token. After the tag push, do not block on the image build: start one background `gh run watch <run-id> --exit-status --interval 30` Bash task for the tag-triggered image workflow, tell the user the build is running, and end the turn. When the background task completes with success, dispatch Build Checker to verify the five native sources (tag commit vs main HEAD, Actions run, GitHub Release, GHCR digest, SBOM + provenance) and report the Release URL and digest to the user — no Work Item state is written anywhere in this flow. On build failure or a missing registry digest, report the failure reason with the run URL and STOP for human handling; never retry the tag automatically.
