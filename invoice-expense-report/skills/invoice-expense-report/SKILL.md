# Invoice Expense Report

## Overview

整理发票（高铁票、机票、滴滴票、酒店发票、酒店结账单）并生成报销统计 Excel。**全 PDF 内容驱动**（文件名/目录名只作分类提示，字段一律从 PDF 提取），自动匹配发票↔结账单。

核心流程：**还原行程链 → 完整性人工确认 → 确认项目名 → 补贴天数人工确认 → 按出差生成报告 + Excel**。凡是"人工确认"环节，必须等用户回复后才继续，不得自作主张。

## When to Use

- 用户说"整理发票"、"报销"、"出差补贴"、"检查发票齐不齐"
- 出差目录下有高铁票/机票/滴滴票/酒店发票需合并统计
- 多段行程（一次报销多个城市出差）需统一聚合、按出差出报告

## Input Requirements

**目录结构（常见）：** `<根目录>/<城市>出差/{高铁,机票,滴滴,酒店}/xxx.pdf`，可能还有 `机票退费/` 等特殊目录。目录名是分类提示，最终以 PDF 内容为准。

**文件类型（混合识别）：**
- 高铁票电子发票 PDF — 含 `铁路电子客票` / 车次 `G\d+` 等
- 机票行程单 / 航空电子客票 PDF — 含航空公司、航班号、起降机场
- 滴滴电子发票 PDF — 销售方为滴滴系公司（滴滴出行/小桔科技等），品名 `*运输服务*客运服务费`；可能附带**行程单 PDF**（含上车时间、起终点）
- 酒店电子发票 PDF（销售方为酒店管理公司）/ 酒店结账单 PDF（销售方为酒店品牌，如"汉庭"）

**Excel 模板列：** `ID, 客户名称, 类型, 源, 目标, 费用(元), 备注`（"客户名称"列填**项目名**，见第 4 步）

## Core Pattern

### 1. 扫描 + 自动分类

```bash
ls -la <目录> && find . -name "*.pdf"
```

对每个 PDF 提取文本并判断类型：
- 含 `铁路电子客票` / `G\d+` → **火车票**
- 含航空公司/航班号/机场码 → **机票**
- 销售方含 `滴滴`/`小桔` 或品名含 `客运服务费` → **滴滴发票**
- 含 `住宿服务`/`住宿费` + `价税合计` → **酒店发票**
- 含 `结账单` + `入住日期` + `离店日期` → **酒店结账单**

文本提取：

```python
from pypdf import PdfReader
import re

def extract_text(p):
    r = PdfReader(p)
    return "\n".join(pg.extract_text() for pg in r.pages)
```

### 2. PDF 字段提取

**火车票：**
```python
def parse_train(text):
    price = re.search(r'票价\s*[:：]?\s*¥\s*(\d+\.\d{2})', text)
    date = re.search(r'(\d{4})\s*年\s*(\d{1,2})\s*月\s*(\d{1,2})\s*日', text)
    dep_time = re.search(r'(\d{2}):(\d{2})\s*开', text)
    stations = re.findall(r'(?:Changshanan|Wuxi|Xiamenbei|Shenzhenbei|Changsha|Wuhan)[A-Za-z]*', text)
    train_no = re.search(r'\b([GDKCTZ]\d+)\b', text)
    return {'price': float(price.group(1)) if price else None,
            'date': f"{date.group(1)}-{int(date.group(2)):02d}-{int(date.group(3)):02d}" if date else None,
            'dep_time': dep_time.group(0) if dep_time else None,
            'train_no': train_no.group(1) if train_no else None,
            'from': stations[0] if stations else None,
            'to': stations[-1] if len(stations) >= 2 else None}
```

**滴滴发票/行程单：**
```python
def parse_didi(text):
    total = re.search(r'价税合计[^\d]*?¥\s*(\d+\.\d{2})', text)
    # 上车时间：行程单或发票备注，如 "行程开始时间: 2026-08-30 23:45"
    ride = re.search(r'(?:行程|用车|乘车)[^\d]{0,6}(\d{4}-\d{2}-\d{2})[ T]*(\d{1,2}:\d{2})', text)
    return {'total': float(total.group(1)) if total else None,
            'ride_time': f"{ride.group(1)} {ride.group(2)}" if ride else None}
```

⚠️ **滴滴发票 PDF 经常没有行程明细**（只有金额和开票日期）。时间/起终点信息缺失时，**必须把该发票列出来问用户**（哪天、几点上车、从哪到哪）——24 点规则判定依赖上车时间，不能猜。

**酒店发票：**
```python
def parse_hotel_invoice(text):
    total = re.search(r'价税合计[^\d]*?¥\s*(\d+\.\d{2})', text)
    seller = re.search(r'销\s*售\s*方\s*信\s*息.*?名\s*称\s*[:：]\s*(\S+)', text, re.S)
    buyer = re.search(r'购\s*买\s*方\s*信\s*息.*?名\s*称\s*[:：]\s*(\S+)', text, re.S)
    stay = re.search(r'入离日期\s*[:：]?\s*(\d+[-/]\d+)\s*至\s*(\d+[-/]\d+)\s*[,，]?\s*共\s*(\d+)\s*天', text)
    return {'total': float(total.group(1)) if total else None,
            'seller': seller.group(1).strip() if seller else None,
            'buyer': buyer.group(1).strip() if buyer else None,
            'stay': stay.groups() if stay else None}
```

**酒店结账单：**
```python
def parse_hotel_bill(text):
    check_in = re.search(r'入住日期\s*[:：]?\s*(\d{4}[-/]\d{1,2}[-/]\d{1,2})', text)
    check_out = re.search(r'离店日期\s*[:：]?\s*(\d{4}[-/]\d{1,2}[-/]\d{1,2})', text)
    amount = re.search(r'消费合计\s*(\d+(?:,\d{3})*\.\d{2})', text)
    hotel_name = re.search(r'^(.+?)\s*结账单', text, re.M)
    return {'check_in': check_in.group(1) if check_in else None,
            'check_out': check_out.group(1) if check_out else None,
            'amount': float(amount.group(1).replace(',', '')) if amount else None,
            'hotel_name': hotel_name.group(1).strip() if hotel_name else None}
```

### 3. 行程还原 + 完整性检查（必须人工确认）

把所有交通票据按时间排序，还原每次出差的行程链，**逐项核对是否缺票**，输出确认表给用户。

**每次出差的标准行程链（以 长沙↔无锡 为例）：**

| 环节 | 应有票据 | 说明 |
|------|---------|------|
| ① 去程交通 | 长沙→无锡 高铁票**或**机票（任一即可） | 高铁、飞机都行 |
| ② 到达滴滴 | 高铁站/机场 → 酒店（或客户） | 落地后接驳 |
| ③ 住宿 | 酒店发票 + 结账单 | 当日往返无此项 |
| ④ 返程滴滴 | 酒店 → 高铁站/机场 | 回程前接驳 |
| ⑤ 回程交通 | 无锡→长沙 高铁票或机票 | |
| ⑥ 到家滴滴（长沙） | 见下方 24 点规则 | 多数情况不可报 |

**输出完整性确认表（示例格式，日期必须带星期几）：**

```
【无锡出差 08-30(周日) ~ 09-02(周三)】
① 去程交通  ✅ 长沙南→无锡东 G1727 08-30(周日) 07:35开 ¥349
② 到达滴滴  ✅ 无锡东→酒店 08-30(周日) 14:20 ¥45
③ 住宿      ✅ 汉庭无锡站店 08-30(周日)~09-02(周三) 3晚 ¥960（发票+结账单齐）
④ 返程滴滴  ❌ 缺：酒店→无锡东 滴滴票
⑤ 回程交通  ✅ 无锡东→长沙南 G1728 09-02(周三) 19:02开 ¥349
⑥ 到家滴滴  ⚠️ 09-02(周三) 23:40 上车 → 未过24点，默认不报销
```

**日期显示规范：** 所有打印给用户确认的表格（完整性确认表、补贴天数确认表），日期一律带星期几，便于用户核对行程顺序和周日补贴口径。

```python
from datetime import datetime
WEEK_CN = ['周一','周二','周三','周四','周五','周六','周日']
def fmt_date(d):  # '2026-08-30' → '08-30(周日)'
    return f"{d[5:]}({WEEK_CN[datetime.strptime(d, '%Y-%m-%d').weekday()]})"
```

**规则：**
- ❌ 缺失项和 ⚠️ 存疑项**必须逐条让用户确认**：是补票、还是确实没产生（同事接站/步行/住在客户处），确认结果写入备注
- 用户确认完毕前，不进入下一步

**滴滴可报性判定规则：**

| 场景 | 可否报销 |
|------|---------|
| 出差城市：站/机场 ↔ 酒店/客户 | ✅ 可报 |
| 常驻城市（长沙）：回程后打车回家，上车时间**过了当天 24 点**（即次日凌晨） | ✅ 可报 |
| 常驻城市（长沙）：回程后打车回家，上车时间**在 24 点前**（当晚） | ❌ 不报（到达时间没过 24 点就不报销） |

- 时间来源优先级：滴滴行程单上车时间 > 发票备注行程时间 > 回程交通票时间推断 > **问用户**
- 判定结果只做标注和建议，边界情况（如 23:50 / 00:10）列出来让用户拍板

### 4. 项目名确认（每个出差）

- 每个出差目录（如 `无锡出差/`、`厦门出差/`）对应一个**项目**，项目名**必须问用户**（用户消息里已给出则直接用），不要从文件名或发票猜
- 确认格式：`无锡出差 → 项目「XX客户数字化项目」`，全部确认后再生成
- 项目名用途：Excel "客户名称"列、报告标题、报销单归属
- 特殊目录（如 `机票退费/`）先问用户口径：退票手续费计入哪次行程、全额退款如何处理，不要自行决定正负号

### 5. 发票 ↔ 结账单 匹配

**强匹配规则（按优先级）：**
1. 金额相同 + 入住日期在 ±1 天 → 强匹配
2. 金额相同 + 入住日期不可用 → 弱匹配（需提示确认）
3. 都不匹配 → 孤儿，提示用户

**品牌 vs 管理公司：** 结账单酒店名（如"汉庭"）与发票销售方（如"深圳市五嘉酒店管理有限公司"）可能不同，用金额 + 日期匹配，不强制名称一致。

### 6. 住宿天数计算（明确口径，仅指住宿发票/结账单的"X天"）

- 住宿口径的 "X 天" = **X 晚**（中文酒店行规）：6-08 入住、6-12 离店 = **4 天**（不是 5 天）
- 计算公式：`住宿天数 = (离店日 - 入住日).days`
- ⚠️ 这是住宿行规口径，**不是补贴天数**——补贴按第 7 步"晚数+1"另算

```python
from datetime import datetime
def stay_days(check_in, check_out):
    d1 = datetime.strptime(check_in, '%Y-%m-%d')
    d2 = datetime.strptime(check_out, '%Y-%m-%d')
    return (d2 - d1).days
```

### 7. 补贴天数（建议值 + 人工确认可修改）

**补贴天数不自动定死**：先算建议值，打印确认表，用户可改任何一段，**以用户确认的数字为准**。

**补贴口径（2026-09-24 用户更正）：早出发那天算一天，晚上到家那天也算一天 → 建议值 = 住宿晚数 + 1。**
例：周一早出、周五晚到家，住 4 晚 → 补贴 5 天；像"早上过去、晚上到家"的当天往返 → 1 天。

```
行程       住宿区间                      建议天数       请确认
无锡出差   08-30(周日) ~ 09-02(周三)     3 晚→4天       ?
厦门出差   09-10(周四) 早出晚归当日返    默认1天        ?
```

- 建议值 = **住宿晚数 + 1**（早出、晚归到家各算一天）；**当日往返无住宿的行程默认建议 1 天，必须让用户确认或修改**
- 判定"晚归"以上一趟交通票到达/到家滴滴时间为准（如 09-23 晚班机、09-24 00:21 到家滴滴，也算晚归到家那天）
- 同时问用户：每日补贴标准（常见 ¥100/¥150/¥200）
- 多段行程分别补贴，不合并去重；周日照常（除非用户明示要扣，确认表已带星期几便于核对）
- 用户修改后重新合计；Excel 补贴行备注写明：`5天×¥100（人工确认：早出、晚归到家各算一天）`

### 8. 重命名 + 强校验

改名后立即 `ls` 校验；必填字段（日期、金额）从 PDF 提取而非猜测。

```bash
# 正确：先匹配，再 mv，最后校验
mv "原.pdf" "新.pdf" && ls "新.pdf"
```

**文件名规范：**
- 火车票：`{出发站}-{到达站}-{MMDD}-{金额}.pdf`
- 机票：`{出发城市}-{到达城市}-{MMDD}-{金额}.pdf`
- 滴滴：`{城市}-{起点}-{终点}-{MMDD}-{HHMM}-{金额}.pdf`（缺时间则 `{城市}-{用途}-{MMDD}-{金额}.pdf` 并在报告中标注）
- 酒店发票：`{酒店名(简化)}-{入住MMDD}至{离店MMDD}-{金额}.pdf`
- 酒店结账单：`结账单-{入住MMDD}至{离店MMDD}-{酒店名(简化)}-{金额}.pdf`

### 9. 按出差生成报告 + Excel

**每段出差输出一份报告（对话中输出，用户要文件则存 `<根目录>/出差报告.md`）：**

```

滴滴   酒店→无锡东 09-02                ¥0  ❌缺票（用户确认：同事送站）
回程   无锡东→长沙南 G1728 09-02        ¥349

       晚归到家各算一天）

```

**Excel（openpyxl，按出差时间排序分组）：**
- 列：`ID, 客户名称(=项目名), 类型, 源, 目标, 费用(元), 备注`
- 类型：火车 / 机票 / 滴滴 / 住宿 / 补贴（/ 退票费）；不可报的滴滴**不写入**，只在报告里标注
- 每段出差后加小计行，最后总计行；另附分类小计（火车/机票/滴滴/住宿/补贴）

## Quick Reference

| 类型 | 字段来源 | 备注格式 |
|------|---------|---------|
| 火车 | PDF 全文 | `YYYY-MM-DD Gxxxx HH:MM开` |
| 机票 | 行程单/客票 PDF | `YYYY-MM-DD 航班号` |
| 滴滴 | 发票 + 行程单/用户口述 | `YYYY-MM-DD HH:MM 起点→终点` |
| 住宿 | 发票金额 + 结账单日期 | `YYYY-MM-DD至YYYY-MM-DD 共X天` |
| 补贴 | 人工确认天数 × 标准 | `X天×¥Y/天（人工确认）` |

## Common Mistakes（实战版）

| 错误 | 修正 |
|------|------|
| 假设文件名是语义命名 | **必须从 PDF 提取所有字段** |
| 只数票据不算行程链 | **还原 ①~⑥ 行程链**，缺哪个环节列出来 |
| 回长沙 24 点前的到家滴滴计入 Excel | **不报**，报告中标注；边界时间让用户拍板 |
| 滴滴发票无时间就跳过 24 点判定 | **问用户上车时间**，不能猜 |
| 补贴天数自动定死 | 建议值 + **人工确认表，用户可改**，以确认为准 |
| 确认表日期不带星期几 | 日期一律带星期几（`fmt_date`），便于核对行程顺序与周日口径 |
| 项目名靠猜 | **问用户**，填入"客户名称"列 |
| 缺失环节静默跳过 | 完整性表逐项 ✅/❌/⚠️，等用户确认 |
| 客户名称误识别 | 用购方信息匹配 `统一社会信用代码` + `名称` |
| 把结账单改错名 | 先匹配金额+日期，再 mv，**最后 ls 校验** |
| 酒店无结账单就跳过 | 兜底：发票备注里的"入离日期" → 问用户 |
| 6-08~6-12 算 5 天 | **住宿天数=离店日-入住日（按晚）** = 4 天；这是住宿口径，**补贴=晚数+1** 另算 |
| 补贴建议值=住宿晚数 | 建议值=**晚数+1**（早出、晚归到家各算一天），当日往返=1 天（2026-09 用户更正） |
| Excel 用 patch 改错行 | **整表重建**（openpyxl 行号操作易错乱） |
| 补贴按自然日去重 | 按 晚数+1 各段分别合计（多段不去重） |
| 金额取 `税额` 字段 | 取 **`价税合计`（小写）** |
| 火车备注用开票日 | 用 **乘车日期**（含时间） |
| 结账单酒店名 ≠ 发票销售方 | **不强制匹配名称**，用金额+日期 |

## Workflow Checklist

- [ ] 扫描所有 PDF 并自动分类（火车/机票/滴滴/酒店）
- [ ] 提取每张 PDF 全部字段，打印表格给用户确认（日期一律带星期几）
- [ ] **还原行程链 ①~⑥，输出完整性确认表（✅/❌/⚠️），等用户逐项确认**
- [ ] **滴滴可报性判定（出差城市✅ / 长沙24点规则），无时间信息的问用户**
- [ ] **确认每个出差目录的项目名**（含 机票退费 等特殊目录的口径）
